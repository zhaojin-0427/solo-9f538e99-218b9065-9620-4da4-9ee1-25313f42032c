# 档案馆检索索引核对

旧 OCR 导出为**页×词**矩阵，新软件导出为**词×页**矩阵。本工具提供一个 Flask 核对页：
上传同一册的两套数据，按页键与词对齐核对，确认两套数据能否重建**同一检索索引**；
核对一致时可下载重新整理为旧格式（页×词）的 ZIP 包，解压后可再次上传核对。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发（Python 3.11+）：

```bash
pip install -r app/requirements.txt
python app/app.py          # http://localhost:8000
```

运行测试：

```bash
python3 -I tests/run_tests.py
```

`examples/` 下有一套互相一致的小样例（`old/` 三个文件 + `new/` 三个文件），可直接上传试用。

## 输入格式

每套数据三个文件：

| 文件 | 说明 |
| --- | --- |
| `matrix.mtx` | Matrix Market 通用整数坐标格式：`%%MatrixMarket matrix coordinate integer general`，注释行以 `%` 开头，维度行 `行数 列数 非零项数`，其后每行 `行号 列号 计数`（编号从 1 开始，计数为非负整数） |
| `pages.csv` | 页键单列 CSV（UTF-8、无表头、每行一个），顺序与矩阵页轴一致，**页键唯一** |
| `words.csv` | 词表单列 CSV，顺序与矩阵词轴一致；词**允许重复**（同词的多行/多列将合计） |

旧导出矩阵为 页×词（行=页），新导出矩阵为 词×页（行=词）；矩阵行列数必须与对应 CSV 行数一致。

## 核对规则

- 按页键和词对齐（与两边 CSV 的顺序无关）。
- 重复坐标、同词的多行/多列都合计；未写出的坐标按 0 计。
- 两套数据的页键集合、词集合必须一致（全零的页和词也要核对）。
- 发现缺页、缺词或计数不同时，页面指出一处差异及两边的计数或缺项。
- 格式有误或行列数不符时，页面说明具体原因。

## 输出

两套文件都合法且核对一致才可下载 ZIP，内含：

- `matrix.mtx` —— 页×词稀疏矩阵，按页键与词（字符串）排序并重新编号；
- `pages.csv` / `words.csv` —— 与矩阵轴对应的排序后页键与词表。

解压后即为一套合法的旧格式数据，可再次上传核对。

## 内存设计

核对与打包的内存占用**不随非零项数增长**：

- 矩阵条目流式解析后批量写入磁盘上的 SQLite；
- 合计与排序由 SQLite 在磁盘完成（`temp_store=FILE`，排序溢出到临时文件）；
- 核对时对两条已排序的聚合流做归并比较，任意时刻只持有当前行；
- 打包时矩阵内容先落临时文件，再流式写入 ZIP。

只有页键表、词表及其编号索引驻留内存（随页数/词数增长）。
测试：`tests/run_tests.py` 中 200 万条输入的用例，Python 侧内存峰值 < 64 MB。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `WORK_DIR` | `app/work`（容器内 `/data/work`） | 临时工作目录与 ZIP 存放目录 |
| `DOWNLOAD_TTL_SECONDS` | `3600` | 下载链接有效期 |
| `SQLITE_TMPDIR` | 系统默认（容器内 `/data/tmp`） | SQLite 排序临时文件目录 |
